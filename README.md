# Wireshark-Network-Analysis-Lab
Virtualized security lab built to simulate, capture, and dissect adversarial network attacks against an enterprise Linux target. Two-node isolated network containing a Kali Linux attack box and an Ubuntu target/monitoring sensor. Techniques Analyzed: MITRE ATT&amp;CK T1046 (Network Service Discovery via Nmap SYN and FIN scans) 


WIRESHARK NEWORK TRAFFIC ANALYSIS LAB

1. Project Overview
This project establishes a virtualized Security Operations Center (SOC) packet analysis environment to simulate, capture, and investigate malicious network traffic signatures. Using Kali Linux as an adversary node and Ubuntu Server as the target/sensor node, multiple attack vectors—including Denial of Service (DoS) floods and reconnaissance sweeps—were executed and triaged in Wireshark. 
The primary objective is to differentiate malicious automated activity from benign baseline traffic by analyzing packet header structures, TCP flags, and protocol behavior mapped to the **MITRE ATT&CK framework**.

 3. Attack Execution & MITRE ATT&CK Mapping
The following attack vectors were executed from the Kali Linux adversary machine against the monitored Ubuntu target:

 A. ICMP Flood / Rapid Ping (MITRE ATT&CK: T1498 - Denial of Service)
•	Purpose: Exhaust target network socket buffers and overwhelm processing bandwidth via high-frequency ICMP Echo Requests.
•	Execution Command: sudo hping3 --icmp -i u1000 -c 100 192.168.56.101

B. TCP SYN Stealth Scan (MITRE ATT&CK: T1046 - Network Service Discovery)
•	Purpose: Identify open services across target ports by sending half-open SYN packets without completing the 3-way handshake.
•	Execution Command:
Bash
sudo nmap -sS -p 21,22,80,443,8080 192.168.56.101
C. FIN Stealth Scan (MITRE ATT&CK: T1046 - Network Service Discovery)
•	Purpose: Circumvent stateless firewalls and packet filters by transmitting unsolicited FIN packets to closed vs. open ports.
•	Execution Command:
Bash
sudo nmap -sF -p 21,22,80,443 192.168.56.101
D. TCP SYN Burst (MITRE ATT&CK: T1498.001 - SYN Flood)
•	Purpose: Simulate half-open resource exhaustion against port 80 to disrupt legitimate web services.
•	Execution Command:
Bash
sudo hping3 -S -p 80 -c 100 --fast 192.168.56.101
E. Benign Baseline Generation
•	Purpose: Inject standard HTTP/DNS traffic to contrast against malicious streams.
•	Execution Command:
Bash
curl -I [http://192.168.56.101](http://192.168.56.101)
4. Wireshark Triage & Filter Reference
Triage Objective	Wireshark Display Filter	Packet Signature & Forensic Indicators
ICMP Flood Detection	icmp.type == 8	Identifies bursts of high-rate ICMP Echo Requests arriving within milliseconds.
SYN Scan / Flood Triaging	tcp.flags.syn == 1 && tcp.flags.ack == 0	Isolates half-open [SYN] connection attempts lacking corresponding [ACK] confirmations.
Closed Port Rejections	tcp.flags.reset == 1	Displays [RST, ACK] packets generated by the target OS rejecting connections to closed ports scanned by Nmap.
FIN Scan Anomalies	tcp.flags.fin == 1 && tcp.flags.ack == 0	Detects abnormal teardown requests sent without prior established TCP sessions.

6. Key Takeaways & Defense Recommendations
1.	Signature vs. Anomaly Detection: Automated port scans and packet floods leave distinct TCP flag combinations and abnormal request rates that can be systematically filtered using Layer 3/4 inspection.
2.	IDS/IPS Rule Creation: The captured patterns provide the baseline for writing custom Snort/Suricata rules (e.g., alerting on $>20$ SYN packets without ACK within 5 seconds from a single IP).
3.	Firewall Hardening: Implementing rate-limiting on ICMP traffic and dropping unsolicited FIN packets at the perimeter prevents internal network topology mapping.
